# WebSocket 消息推送优化说明

## ✅ 已完成的优化

### 1. 消息去重机制

**实现方式**：
- 在 `Manager` 中添加 `lastPushState` map，缓存上次推送的状态
- 比较当前状态与上次推送状态，只在有变化时推送

**去重规则**：
- 状态变化：必须推送
- 进度变化超过阈值（0.5%）：推送
- 行数变化：推送（但受频率限制）
- 其他变化（如速度）：不推送，减少网络流量

**文件修改**：
- `internal/task/manager.go` - 添加 `taskPushState` 结构和去重逻辑

---

### 2. 推送频率限制

**实现方式**：
- 添加 `MinPushInterval` 常量（1秒）
- 在 `lastPushTime` map 中记录上次推送时间
- 检查推送间隔，太频繁则跳过

**配置**：
- `MinPushInterval = 1000` 毫秒（可在 `constants.go` 中调整）

**文件修改**：
- `internal/task/constants.go` - 添加 `MinPushInterval` 常量
- `internal/task/manager.go` - 添加频率限制检查

---

### 3. 智能推送逻辑

**推送条件**：
1. 首次推送（无缓存状态）
2. 任务状态变化（必须推送）
3. 进度变化超过阈值（0.5%）
4. 行数变化（但受频率限制）

**不推送情况**：
- 进度变化小于阈值且行数未变化
- 推送间隔小于最小间隔
- 仅速度变化但进度未变化

**预期效果**：
- 减少网络流量 50-70%
- 降低服务器 CPU 使用率
- 提升用户体验（减少不必要的更新）

---

### 4. 前端连接状态指示器

**实现方式**：
- 添加 `wsConnectionStatus` ref，跟踪每个任务的连接状态
- 在进度列显示连接状态图标
- 三种状态：已连接（绿色）、重连中（橙色）、已断开（红色）

**状态管理**：
- `connected` - 连接成功，实时更新正常
- `reconnecting` - 正在重连中
- `disconnected` - 连接断开

**UI 显示**：
- 图标：✅ 已连接、🔄 重连中、❌ 已断开
- 颜色：绿色、橙色、红色
- 提示：鼠标悬停显示详细状态

**文件修改**：
- `web/src/views/TaskView.vue` - 添加状态指示器和相关函数

## 📊 优化效果

### 推送频率对比

**优化前**：
- 每 500ms 推送一次
- 每个任务每秒推送 2 次
- 10 个任务 = 20 次/秒

**优化后**：
- 智能推送：只在状态变化或进度变化超过阈值时推送
- 频率限制：最小间隔 1 秒
- 实际推送频率：约 0.5-1 次/秒/任务（取决于进度变化速度）

**预期减少**：
- 网络流量：减少 50-70%
- 服务器 CPU：降低 30-50%
- 前端更新：更流畅，减少不必要的重渲染

// MinPushInterval 最小推送间隔（毫秒）
MinPushInterval = 1000 // 默认 1 秒

// ProgressChangeThreshold 进度变化阈值（百分比）
ProgressChangeThreshold = 0.5 // 默认 0.5%

// MonitorInterval 任务监控间隔（毫秒）

## 📝 注意事项

1. **向后兼容**：
   - 消息格式保持不变
   - 前端无需修改消息处理逻辑

2. **状态清理**：
   - 任务停止时自动清理推送状态缓存
   - 避免内存泄漏

3. **首次推送**：
   - 首次推送总是执行（无缓存状态）
   - 确保前端能及时收到初始状态

4. **状态变化推送**：
   - 任务状态变化（如 running -> completed）总是推送
   - 确保前端能及时响应状态变化
