# 改进建议清单

## 🚀 高优先级改进

### 1. WebSocket 消息推送优化 ⚠️

**当前问题**：
- 每 500ms 推送一次，可能过于频繁
- 没有消息去重机制（相同状态可能重复推送）
- 没有连接状态指示器

**改进方案**：
- [ ] 实现智能推送：只在状态变化或进度变化超过阈值时推送
- [ ] 添加消息去重：缓存上次推送的状态，避免重复推送
- [ ] 添加推送频率限制：可配置的最小推送间隔
- [ ] 添加连接状态指示器：前端显示连接状态（已连接/断开/重连中）

**预期收益**：
- 减少网络流量 50-70%
- 降低服务器 CPU 使用率
- 提升用户体验（减少不必要的更新）

---

### 2. 错误处理统一迁移 ⚠️

**当前状态**：
- 已创建统一的错误处理机制
- 但仍有 20+ 个 handler 使用旧的 `c.JSON` 方式

**需要迁移的文件**：
- `handler_additions.go`（部分已迁移）
- `handler_task.go`（部分已迁移）
- `handler_connection.go`
- `handler_database.go`
- `handler_template.go`
- `handler_preview.go`
- `handler_importexport.go`
- `handler_scheduler.go`
- `handler_relationship.go`
- `handler_preset.go`
- `handler_history.go`
- `handler_quality.go`
- `handler_monitor.go`

**改进方案**：
- [ ] 批量迁移所有 handler 使用 `sendError`/`sendSuccess`
- [ ] 统一错误响应格式
- [ ] 添加错误码映射文档

**预期收益**：
- 统一的错误处理体验
- 更好的错误追踪和调试
- 前端错误处理更简单

---
